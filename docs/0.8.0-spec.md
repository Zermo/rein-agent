# Rein 0.8.0 implementation contract

Source: the owner's requests in the September 5, 2026 implementation conversation.
Baseline: `0cc5d69cf21f21eb10803f5239fc3d885204686f` (0.7.0).

## Requested behavior

- "Explicit Chat Completions setup and compatibility": make the HTTP protocol
  visible in setup/configuration while preserving custom proxy paths, remote
  loopback/SSH support, JSON and SSE replies, and official subscription CLI login.
  This does not request a server exposing Rein as a Chat Completions API.
- "add ... bash tmux support": offer persistent bash sessions to the agent and
  user with start, list, capture, literal input, interrupt, stop, and attach.
  Ordinary foreground bash and its cancellation must continue to work.
- "split the terminal cli window into a canvas/ node workflow ... commands and
  execs and writes visually ... watch the agent work": provide a split terminal
  activity view and an interactive local node canvas with real requests,
  visible responses, thinking status, tool inputs/results/progress, and file paths.
  Selection, pan, zoom, follow-live, and keyboard access must work. Do not invent
  a reasoning trace or display private hidden reasoning.
- "hardcode https://github.com/boldsoftware/meat": embed the pinned actual Meat
  algorithm, including validated edit plans and original-diff preservation. Use
  the active Rein model connection for inference. Expose CLI and agent-tool
  entry points, with bounded execution, cancellation, provenance and licensing.

## Integration choices and limits

The Meat Go package runs as bundled WASM in a Node worker, with no Go installation
required by users. Source inspection stays in a scoped, bounded host. Its grep
adapter advertises literal search and its read adapter advertises exclusions.
The result is a reading diff; it is not an applicable patch or a correctness proof.

Tmux servers belong to Rein, with workspace filtering. Visual sessions use a
separate socket from agent-controlled shells. Persistent shells survive `/stop`
and detach; foreground jobs must end when their harness is stopped. No process
injection, unrelated process adoption, or machine-wide service changes are part
of this release.

Activity is opt-in via `--visual` or `--activity <fresh UUID>`. It is separate from
Posthorse and never changes the cached model prefix. A private bounded snapshot
backs a loopback-only, token-protected browser view. The view displays observable
execution, not the entire archived transcript. Existing Nodeterm hooks remain
available without bundling its BUSL-1.1 application.

## Release acceptance

Source regression tests, actual tmux fixtures, browser interaction checks,
Node 18 bundled Meat execution, pinned upstream source tests and reproducible
WASM verification must pass. Commit and push the changes, then update and verify
the previously installed CLI. Check the remote CI run for the pushed revision.
