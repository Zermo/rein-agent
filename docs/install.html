01
Install the CLI

Run these commands in a normal NodeTerm shell tab.

Put Rein in your terminal.

NodeTerm hosts the terminal. Rein is the command you install inside it. Start with a working Node.js installation and these command-line tools.

Node.js 18+npmgitcurl + Bash
CHECK YOUR TOOLS
node --version
npm --version
git --version
curl --version

If one is missing, install it before continuing. Node includes npm. Get Node.js from its official site. The Bash installer supports macOS, Linux, and WSL.

INSTALL / LEAVE MODEL SETUP FOR STEP 02
curl -fsSL https://raw.githubusercontent.com/Zermo/rein-agent/main/install.sh \
  | bash -s -- --skip-setup

--skip-setup installs the latest build without checking a saved model connection. Your settings and session history stay in place.

LOOK FORinstalled · rein <version> · setup skipped
"rein: command not found" after installing?

Open a fresh NodeTerm shell. If it still cannot find Rein, check the global npm location:

npm prefix -g

On macOS and Linux, its bin directory must be on your shell's PATH. The installer prints the exact path when it detects this problem.

02
Choose a model

Same Rein. Pick the connection that matches where your model runs.

Make the connection.

You can use a local server, your model-host, a supported subscription CLI, or a cloud API key. Choose your route below.

Your model-host, over SSH.

Keep the model server running on the model-host. Make sure NetBird is connected and your model-host SSH alias works.

MAC / NODETERMRein opens the tunnel
→
model-host / MODEL SERVER127.0.0.1:8123 on the model-host

Localhost belongs to the model-host here. With --ssh model-host, Rein forwards to the remote machine's loopback address. You can keep the server bound to 127.0.0.1.

CHECK SSH, THEN CONFIGURE REIN
ssh -o BatchMode=yes model-host true &&
rein setup --ssh model-host --base-url 127.0.0.1:8123 \
  --api chat-completions

Choose a loaded model when asked. If the local server does not require a key, leave the API-key prompt blank. API key: not saved is expected for a server that accepts unauthenticated requests.

Why not use the model-host's NetBird IP as the base URL?

A server bound only to 127.0.0.1 is reachable from that server itself. Its NetBird IP identifies the machine, but does not make the loopback-only API listen on the network. The SSH tunnel connects those two pieces.

If your API already listens on its NetBird interface, a direct HTTP connection is also possible. Use that actual listening address and port in setup.

The SSH check fails or says "Could not resolve hostname model-host".

The model-host name must be a working SSH alias or a resolvable host. Add an entry to ~/.ssh/config using your actual NetBird address and model-host username:

Host model-host
    HostName YOUR_NETBIRD_IP
    User YOUR_model-host_USER

Replace both placeholders. First connect with ssh model-host to verify the host and set up your normal key-based login. Rein opens tunnels non-interactively, so the BatchMode=yes check must pass.

A model on this computer.

Start your model server and load a model. Then open the setup wizard. Rein can discover common local servers such as Ollama, LM Studio, llama.cpp, and vLLM.

AUTO-DETECT A LOCAL SERVER
rein setup

If discovery misses it, choose the custom API option and paste the server URL shown in your model app. On this route, 127.0.0.1 means the computer running Rein.

Sign in with a supported account.

Rein delegates subscription authentication to the official Codex or Copilot CLI. Install the one you use, then run its Rein setup command.

CHATGPT THROUGH CODEX
npm install -g @openai/codex
rein setup --provider codex
OR, GITHUB COPILOT
npm install -g @github/copilot
rein setup --provider copilot

Follow the device-code or browser sign-in shown by the CLI. Use an account eligible for that service. These connections manage their own transport and credentials.

A cloud API key.

Use a provider API key for direct HTTP requests. API billing is separate from a chat subscription. This example selects OpenAI's Chat Completions API.

INTERACTIVE CLOUD SETUP
rein setup --provider openai --api chat-completions

Setup opens the provider's key page when supported. Enter the key at the hidden terminal prompt and choose a model available to your account. For another provider or a custom base URL, use rein setup and choose it in the wizard.

03
First contact

A successful check means Rein can talk to the selected model.

Ask for a small hello.

Verify the saved connection, then make a short request with tools disabled.

VERIFY AND SEND A TEST MESSAGE
rein setup --status &&
rein --no-tools -p "Reply with the single word: ok"
LOOK FORconnection: passed, followed by a short model reply

Then move into the project you want Rein to work on and run rein. Your current directory gives its file and shell tools their working context.

For chat alongside a live activity view, install tmux and start rein --visual. Ordinary chat does not require tmux.

04
Keep current

Install once. Update from the same terminal.

Fresh build. Same home.

Fetch the current published installer and update Rein. Your model can be offline while this runs.

UPDATE THE INSTALLED BUILD
rein update && rein --version

Restart any running Rein sessions after updating. Your configuration, notes, and saved sessions remain in ~/.rein, or your custom REIN_HOME.

My version does not have "rein update" yet.

Use the curl command in step 01. It runs the same installer with model setup skipped.

The updater found local changes in its checkout.

Commit or move those changes before updating. The installer preserves edits in its ~/.rein/repo checkout. It does not overwrite them to force an update.

If a light
stays red

"No valid chat completion" with Qwen or another reasoning model

Update Rein first. Older setup probes allowed only eight output tokens. A reasoning model could use that budget before returning visible text, even though the server answered correctly. v0.9.3 gives the probe more room and recognizes supported reasoning responses.

Then rerun rein setup --status. A response that still lacks a completion needs investigation; an HTTP 200 status alone is not enough.

"SSH connection failed", a timeout, or connection refused

Check that NetBird is connected, the model-host is awake, and its model app is serving on the configured port. Run the SSH check in step 02. With an SSH route, the model app can remain bound to loopback.

HTTP 401, HTTP 403, or an unknown model

Check the selected provider, account or API key, and model ID. Run rein setup to choose from the server's model list. A missing saved key is only a problem if that server requires one.

I want to use native Windows without WSL.

Use npm to install the prebuilt CLI, then start setup:

npm install --global git+https://github.com/Zermo/rein-agent.git
rein setup

Rerun the npm installation command to update. The curl/Bash updater and tmux route in this guide use macOS, Linux, or WSL.
