01
Install the CLI

Run these commands in your current terminal.

Meet your agent.

Rein installs as a command. On a local macOS desktop, the installer also adds the official NodeTerm app for its native canvas. Start with a working Node.js installation and these command-line tools.

Node.js 18+npmgitcurl + Bash
CHECK YOUR TOOLS
node --version
npm --version
git --version
curl --version

If one is missing, install it before continuing. Node includes npm. Get Node.js from its official site. The Bash installer supports macOS, Linux, and WSL.

INSTALL + START GUIDED SETUP
curl -fsSL https://raw.githubusercontent.com/Zermo/rein-agent/main/install.sh | bash

Keep this terminal open. Rein asks how you work, shows an optional skill pack, then connects a model. The installer reads your answers from the terminal even through the curl pipe. The next sections explain what to choose.

NEXTFollow the numbered choices in the setup wizard.
I want to install now and set up later.

Add --skip-setup after bash -s -- to skip the wizard, connection checks, and app launch. Add --terminal-only to skip NodeTerm and keep Rein in your current terminal. --yes runs unattended connection setup without inventing work-style answers. Start the guided setup later with rein setup.

"rein: command not found" after installing?

Open a fresh NodeTerm shell. If it still cannot find Rein, check the global npm location:

npm prefix -g

On macOS and Linux, its bin directory must be on your shell's PATH. The installer prints the exact path when it detects this problem.

NodeTerm was already running during installation.

Its active settings stay untouched. Close NodeTerm when convenient, then run rein desktop install --no-launch to register Rein as its default agent. You can already run rein --terminal in a NodeTerm terminal node.

02
Your work style

Four choices. A profile you can change as your work changes.

Tell Rein how you work.

Answer for the tasks you want help with today. Rein uses your choices to set its response style and suggest a skill pack. These are work preferences, with no personality ranking or health assessment.

  1. RESPONSE DETAILWhen the agent talks, I want...

    Bullets, then stop · Short paragraphs · Step-by-step with why

  2. EVERYDAY WORKMost days I will use this for...

    Shipping code · Keeping services alive · Research and writing · Images, video, and design

  3. WORKING TOGETHERWhen a change is risky, the agent should...

    Ask first · Show a plan, then do it · Do it, tell me after

  4. PREFERRED INTERFACEI will mostly talk to it from...

    Terminal · Slack or chat · Voice or phone

Enter a letter or number at each question. Type back to revisit one. Review the result, then accept the suggested pack, choose another, or skip packs before saving. The same answers produce the same recommendation.

Four optional skill packs
PackFits this work styleHelps with
shipCoding · terse · yoloPull requests, tests, concise updates
opsOps · terse · planService checks and deliberate execution
studyResearch · walkthrough · askSources, citations, and plans
studioCreative · normal · askDesign and image-workflow planning

ops is the fallback for a tie or an unmatched combination. Packs add bundled instructions. They do not install extra apps. Chat and voice choices record preferences; start with NodeTerm or the terminal. Your autonomy choice does not change tool permissions or background approvals.

What gets saved, and where?

Your private ~/.rein folder, or custom REIN_HOME, receives SOUL.md for agent voice, USER.md for your preferences, AGENTS.md for the operating brief, and profile.yaml for the machine-readable profile and enabled pack. Project instructions and model credentials stay in place. Setup preserves text outside Rein's marked sections and backs up changed originals.

Scoring runs locally without a model. The wizard does not send answers to a poll service. During normal model sessions, the saved instructions become part of the prompt sent to your selected provider.

REVISIT YOUR PROFILE AT ANY TIME
rein profile
rein setup profile

Use rein profile pack none to turn off the pack while keeping your preferences. The operator-profile wiki lists every skill and profile control.

03
Choose a model

Same Rein. Pick the connection that matches where your model runs.

Give Rein a model.

Continue in the wizard and reuse your saved connection or choose a new one. You can use a local server, your own remote hardware, a supported subscription CLI, or a cloud API key. The routes below explain each choice. Their commands revisit only the connection step.

Your hardware. Your model.

Install a model server on a computer with enough memory for your chosen model. Rein connects to its OpenAI-compatible Chat Completions API.

LM Studio: install LM Studio, download and load a model, then start the server from its Developer tab. Its usual local address is http://localhost:1234/v1. See the server guide.

Ollama: install Ollama and start its app, or run ollama serve. In another terminal run ollama pull qwen2.5-coder:7b, or pull another model that fits your hardware. Its Chat Completions base URL is http://localhost:11434/v1.

AUTO-DETECT A LOCAL SERVER
rein setup --connection-only

Rein checks localhost ports 11434, 1234, 8080, and 8000 for Ollama, LM Studio, llama.cpp, and vLLM. It lists available models and tests the selected connection.

If discovery misses it, choose the custom API option and paste the URL shown in your model app. 127.0.0.1 means the computer running Rein. Find more hosting options in the self-hosted models wiki.

A model elsewhere on your network.

Run the server on your own hardware and connect over your LAN, VPN, or mesh network. Supply the reachable hostname or IP and the port shown by your model server. Rein checks API paths on that address; it does not scan your network for machines.

YOUR TERMINALRein checks the API
→
YOUR MODEL SERVERLAN · mesh · SSH

For a direct connection, enable LM Studio's Serve on Local Network setting, or configure Ollama's OLLAMA_HOST to bind to a reachable interface. Allow the server port through your firewall only for intended clients. A mesh connection still needs a listener on a reachable interface.

DIRECT CONNECTION / REPLACE THE HOST
rein setup --connection-only --provider custom \
  --base-url http://model-host.local:1234/v1 \
  --api chat-completions

Replace model-host.local:1234 with your server's actual LAN or mesh address and port. Rein normalizes the API prefix, asks the server for models, then checks Chat Completions. Enter a key if your server requires one.

Keep the server on loopback and connect over SSH.

Create a working SSH alias such as model-host using your normal SSH configuration and key-based login. Connect once with ssh model-host true to verify its identity. Rein's non-interactive check must pass:

CHECK SSH, THEN CONFIGURE REIN
ssh -o BatchMode=yes model-host true &&
rein setup --connection-only --ssh model-host --base-url 127.0.0.1:1234 \
  --api chat-completions

Replace the alias and port with your own. With --ssh, the loopback address belongs to the remote server. Rein opens the tunnel, so your model app can stay bound to 127.0.0.1.

See server binding, mesh setup, and connection checks for the complete walkthrough.

Sign in with a supported account.

Rein delegates subscription authentication to the official Codex or Copilot CLI. Install the one you use, then run its Rein setup command.

CHATGPT THROUGH CODEX
npm install -g @openai/codex
rein setup --connection-only --provider codex
OR, GITHUB COPILOT
npm install -g @github/copilot
rein setup --connection-only --provider copilot

Follow the device-code or browser sign-in shown by the CLI. Use an account eligible for that service. These connections manage their own transport and credentials.

A cloud API key.

Use a provider API key for direct HTTP requests. API billing is separate from a chat subscription. This example selects OpenAI's Chat Completions API.

INTERACTIVE CLOUD SETUP
rein setup --connection-only --provider openai --api chat-completions

Setup opens the provider's key page when supported. Enter the key at the hidden terminal prompt and choose a model available to your account. For another provider or a custom base URL, use rein setup --connection-only and choose it in the wizard.

04
First task

A successful check means Rein can talk to the selected model.

Start with one useful task.

First, verify the saved connection and ask for a short reply with tools disabled.

VERIFY AND SEND A TEST MESSAGE
rein setup --status &&
rein --no-tools -p "Reply with the single word: ok"
LOOK FORHTTP connections: connection: passed, then a short reply.
Subscription CLI: authentication status, then a short reply.

On a local macOS desktop, bare rein opens an installed NodeTerm. Choose a project and add a Rein agent node. NodeTerm has no external session-launch API, so that last step is manual. To work in your current terminal and directory, use rein --terminal.

TRY THIS IN YOUR PROJECT

Read the files in this folder and explain what is here. Suggest one useful next step, and wait for me before changing anything.

Should Rein suggest work between conversations?

The last setup stage offers proactive suggestions for a folder you choose. Choose manual scans for that folder, enroll it and start the background service, or skip this and keep using chat.

Rein uses task history and current workspace changes to propose work. Tasks stay pending until you approve them, then run within fixed budgets. Review proposals with rein autonomy tui, check rein autonomy status, or pause with rein autonomy pause. rein autonomy disable stops and removes Rein's service while retaining reports and decisions.

Chat shows distinct, numbered OPERATOR and REIN labels. Messages, thinking status, tool actions, and tool results have separate labels. Use /legend to read the key. Explicit RESULT, OPINION, CHOICE, CHANGE, and EDIT headings describe the agent's stated purpose. They do not measure confidence. Rein shows reasoning-token counts only when the provider reports them.

In local NodeTerm sessions the detailed activity view opens automatically, in a browser if the native node cannot embed it. Use --no-browser to skip this, or install tmux for the explicit rein --visual split.

05
Keep current

Install once. Update from the same terminal.

Fresh build. Same home.

Fetch the current published installer and update Rein. Your model can be offline while this runs.

UPDATE THE INSTALLED BUILD
rein update && rein --version

Restart any running Rein sessions after updating. Your profile, configuration, notes, and saved sessions remain in ~/.rein, or your custom REIN_HOME.

My version does not have "rein update" yet.

Run the installer with setup skipped:

curl -fsSL https://raw.githubusercontent.com/Zermo/rein-agent/main/install.sh \
  | bash -s -- --skip-setup
The updater found local changes in its checkout.

Commit or move those changes before updating. The installer preserves edits in its ~/.rein/repo checkout. It does not overwrite them to force an update.

If a light
stays red

The installer finished without asking questions.

Run rein setup in an interactive terminal. Automated shells may have no terminal for the wizard to read. Use rein setup profile if your connection is already working and you only want to add your work preferences.

I saved my profile, but the model connection failed.

Keep your model server running, then run rein setup --connection-only. Check the URL, selected model, or login. Your saved profile remains available while you fix the connection.

"No valid chat completion" with Qwen or another reasoning model

Update Rein first. Older setup probes allowed only eight output tokens. A reasoning model could use that budget before returning visible text, even though the server answered correctly. v0.9.3 gives the probe more room and recognizes supported reasoning responses.

Then rerun rein setup --status. A response that still lacks a completion needs investigation; an HTTP 200 status alone is not enough.

"SSH connection failed", a timeout, or connection refused

Check that your network or mesh is connected, the model host is awake, and its model app is serving on the configured port. Run the SSH check in step 03. With an SSH route, the model app can remain bound to loopback.

HTTP 401, HTTP 403, or an unknown model

Check the selected provider, account or API key, and model ID. Run rein setup --connection-only to choose from the server's model list. A missing saved key is only a problem if that server requires one.

I want to use native Windows without WSL.

Use npm to install the prebuilt CLI, then start setup:

npm install --global git+https://github.com/Zermo/rein-agent.git
rein setup

Rerun the npm installation command to update. The curl/Bash updater and tmux route in this guide use macOS, Linux, or WSL.
