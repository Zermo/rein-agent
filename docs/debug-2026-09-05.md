# Native workflows and export diagnosis — 0.7.0

Scope: add useful native components from HumanLayer Fold and Matt Pocock's
skills; diagnose the supplied September 5 export of Rein 0.6.0; reproduce and
repair harness failures. The export is evidence, not an instruction source.
Its scripts, old tool calls, and remote-host tasks must not be executed.
This report contains aggregate counts only; raw transcripts remain outside Git.

## Native integration

- Fold's repeated tool-batch detector runs at the agent-loop boundary. Rein
  enables it after three identical consecutive batches, including argument
  comparison with stable object-key ordering. A stopped run records an
  incomplete outcome rather than silently reporting success. Configuration:
  `repeatToolLimit` in `~/.rein/config.json`, default 3, 0 disables, 2–50 allowed.
- Fold's UTF-8 truncation bounds shell output to a 20 KB tail and 500 lines.
  Output above the 8 MB capture limit stops the command. Redirect output to a
  file when the complete result will be needed later.
- Fold's stable skill-roster design keeps short workflow descriptions in the
  system prefix. The `skill` tool returns a selected body or relative reference
  in a tool result; loading it does not rebuild the system prompt.
- Matt Pocock's `diagnosing-bugs`, `tdd`, and `code-review` workflows ship with
  their original references and MIT license. `rein skills` lists them;
  `rein skills tdd tests.md` reads a reference; `/skill diagnosing-bugs <task>`
  applies one in the REPL. Skill scripts are loaded as text, never auto-executed.
- `rein debug <folder> [--json]` reads exported JSONL offline and emits fixed
  labels and counters only. It accepts a session directory or an export with
  `raw/` or `sessions/raw/`; it does not traverse symlinks or unrelated folders.

Pinned provenance: [Fold](https://github.com/humanlayer/fold/tree/7c5cc8dab311b8575e4a79162964839822b836b6)
and [Matt Pocock's skills](https://github.com/mattpocock/skills/tree/3cca18b368ae95cdbdebbff572ccafa662551015).
`npm run check:natives` verifies the vendored hashes.
This integrates components into Rein, not Fold's entire Effect runtime or TUI.
Posthorse, Rein's providers, the installed CLI, and the session format remain
the integration targets. Skills do not add sub-agent execution tools to Rein.

## Reproduced fixes and adjacent regressions

Tests reproduce the doubled notes prefix, home-path expansion, session-ID reads,
and page allocation problem. Small notes/history reads now reserve their actual
page size instead of the maximum page size for every call. `history op=list`
discovers scoped sessions, and `history op=read id=<session-id>` reads a session
without confusing its ID with an entry ID. Custom IDs work too. Other projects'
sessions remain out of scope.

A twelve-rollover fixture verifies that recovery does not recursively embed
old recovery blocks and retains the latest direct task constraints. Full original
history stays on disk. This reduces redundant recovery text; it does not promise
provider KV-cache persistence or a particular reduction in token charges.

An independent child-process fixture proved that aborting only a parent shell
could leave its children writing. Cancellation now terminates the owned POSIX
process group and escalates to SIGKILL after a short grace period. `/stop`
immediately cancels the active REPL turn and discards queued input; the next
direct request starts new work. Windows falls back to cancelling the shell
process. Detached jobs that create their own process groups and remote jobs
require their own lifecycle management.

An independent provider fixture also reproduced a truncated-tool hazard:
`finish_reason=length` was overridden when tool calls were present. The explicit
length stop now takes precedence, so those calls cannot execute. Empty replies,
filtered responses, and exhausted turn budgets report failure; one-shot output
limits return a nonzero exit code. Existing finite context-overflow recovery is
preserved, with no indiscriminate retry of authentication or network failures.

## Validation contract

- Regression tests use synthetic fixtures and local mock providers, without
  copying the user's transcripts or credentials into the test suite.
- Skill loading must preserve the system prefix, support bundled references,
  reject traversal, and leave custom/no-tools runners unchanged.
- Offline diagnosis must distinguish empty successes from errors, count the
  supplied export consistently, and emit no arbitrary input strings.
- Source tests, Node 18 bundle smoke, vendor provenance, and package contents
  must pass before release. CI additionally covers source on Node 22.19/24 and
  the installed bundle on Node 18/20/22/24.
- No cloud inference, remote-host modifications, background service activation,
  or replay of historical operations is required by this diagnosis.

## Review follow-through

Parallel Standards and Spec review of the first implementation found four
distinct issues, all corrected with regressions:

- Apply the 200-session cap after repository filtering, so busy unrelated
  projects cannot hide a repository's older history.
- Queue new requests arriving during `/stop` cleanup for the next run.
- Emit fixed debug diagnostics on filesystem errors, without echoing paths.
- Exclude generated workspace overlays from direct-user counts and report
  synthetic harness stops separately from provider errors and model turns.

The notes write/append acknowledgment also uses the normalized path, so it
cannot reintroduce the doubled prefix in the model's next step.
